# M1 全自动文档分析实测

日期：2026-10-16（Asia/Shanghai）。本报告为脱敏工程证据；原文、详细规则、图像、模型原始输出和详细用例仅保存本地。

## 结果

新增的`analyze-document-m1`已从用户提供的原始DOCX路径开始，自动提取、真实调用本机Codex CLI、编译并校验M1数据、输出报告和用例。没有导入前次会话人工整理的分析JSON，也未修改模型生成的业务内容。

真实运行输出为 **28个需求、28条风险、38个测试点/用例草稿、22条待确认问题**。29张图像均有逐图观察，其中一张思维导图细字无法可靠完整辨认，产生“一处无法解读来源节”和“一处不可读图片”共2项缺口。因此`run.status=BLOCKED`、`analysis_status=PARTIAL_DRAFTS`；这不是整篇分析完备性通过。

所有草稿均保持`DRAFT`、人工审核`PENDING`、游戏执行`NOT_EXECUTED`，M0交接为`BLOCKED`。模型生成的用例数量不代表业务覆盖已充分。

```powershell

python -m ai_test_agent analyze-document-m1 <原始需求DOCX> --output-dir <新的本地运行目录> --provider-config fixtures/m1-provider.codex.example.json --allow-model
```

## 确定性验证与审查

- 全仓库回归：**204项通过**；compileall与差异检查通过。
- 提取器覆盖删除线、tracked deletion、文本框、Word表格、错误worksheet dimension、嵌表、图像、ZIP/XML边界。无法解析的公式和有效附件留有定位和确定性缺口，不会静默当作完整输入。

- 流水线保留未知值、人审队列及M0阻塞，不会在模型失败时切换规则模板并声称AI完成。

- 自动产物后续AI审阅命中了前轮整理的6类关键需求发现，未恢复已删除规则；同时发现2处细粒度用例/状态作用域覆盖遗漏。原始模型输出保持不变，另附本地审查意见，不将AI审阅当作人工批准或完备性证明。
